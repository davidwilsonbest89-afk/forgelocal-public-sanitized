# Internationalization

BrowseForge should support international users in both documentation and application UI.

## Supported Locales

Initial locales:

- `en`
- `zh-TW`

English is the fallback locale for international distribution.

## UI Rules

- Do not hardcode new user-facing Dashboard or extension text without adding locale entries.
- Keep locale keys stable. Rename keys only when the meaning changes.
- Update both `en` and `zh-TW` strings in the same PR.
- Run `node scripts/check-i18n.js` before submitting UI text changes.
- API error `code` values must remain stable and language-neutral. User-facing clients should localize by code when possible.
- Logs and low-level diagnostics may stay English for searchability unless they are shown directly in the UI.

## Dashboard

The built-in Dashboard uses an inline locale table because it is served as a single embedded HTML document. New UI text should use `t("key")` or `data-i18n` attributes.

## Browser Extension

The Firefox extension uses WebExtension `_locales` where possible. Sidebar-specific dynamic strings should use `browser.i18n.getMessage()`.

## Documentation

English is the canonical language for public entry points. Traditional Chinese translations use the `.zh-TW.md` suffix and should link back to the English source.

Public English entry points:

- `README.md`
- `API.md`
- `docker/README.md`
- `docs/README.md`
- `docs/cli.md`
- `docs/local-quickstart.md`
- `docs/cloud-deployment.md`
- `docs/agent-integration.md`
- `docs/developer-integration.md`
- `docs/linux-server.md`
- `docs/platform-support.md`
- `docs/dual-browser-architecture.md`
- `docs/playwright-patches.md`
- `docs/release.md`
- `docs/documentation-language-audit.md`

Traditional Chinese mirrors currently exist for:

- `README.zh-TW.md`
- `API.zh-TW.md`
- `docker/README.zh-TW.md`
- `docs/linux-server.zh-TW.md`
- `docs/platform-support.zh-TW.md`
- `docs/dual-browser-architecture.zh-TW.md`
- `docs/playwright-patches.zh-TW.md`

Historical planning and research notes may remain in their original language while they are not public onboarding entry points. If one of those documents becomes user-facing, create or rename the English canonical document first and move Traditional Chinese content to a `.zh-TW.md` companion.

Run `npm run check-doc-language` before submitting documentation changes that touch public entry points.
